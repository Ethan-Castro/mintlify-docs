## Cloud LLMs vs. local LLMs

<CardGroup cols={2}>
  <Card title="Cloud LLMs" icon="cloud">
    AI models hosted on remote servers by providers like OpenAI, Anthropic, Google, and Microsoft. You send a prompt over the internet; their GPUs run the model; the answer comes back.

    Examples: **ChatGPT, Claude, Gemini, Copilot**.

    Hyperscalers (Meta, Microsoft, Google, AWS) are projected to spend **$700B+** on AI cloud infrastructure this year.
  </Card>
  <Card title="Local LLMs" icon="laptop">
    AI models downloaded and executed directly on your own computer, laptop, or private server — no cloud round-trip.

    Inference engines: **vLLM, SGLang, llama.cpp, Ollama, MLX, LM Studio**.

    Open-weight model families: **Llama, Qwen, Gemma, DeepSeek, GLM, Kimi, Nemotron**.
  </Card>
</CardGroup>

## Benefits of running models locally

<AccordionGroup>
  <Accordion title="Privacy — your data stays with you" icon="shield-halved">
    Local models run directly on your personal device. Prompts, notes, code, research, prescriptions, PII, or confidential files do not need to be sent to a company's cloud server. The model never sees anything you don't hand it.
  </Accordion>
  <Accordion title="Offline access — AI without internet" icon="wifi-slash">
    Once a model is downloaded, it works without WiFi. Useful in classrooms, labs, on a plane, in low-connectivity areas, and in secure environments where outbound traffic is restricted.
  </Accordion>
  <Accordion title="Lower long-term cost" icon="money-bill">
    Instead of paying per prompt or for a subscription, you run the model on hardware you already own. That makes experimentation accessible to students and to small teams that can't expense API spend.
  </Accordion>
  <Accordion title="Environmental awareness" icon="leaf">
    No cloud requests. No round-trips to a data center. Local LLMs use your laptop's existing power budget instead of remote facilities that need large amounts of electricity, cooling, and water.
  </Accordion>
  <Accordion title="Customization" icon="sliders">
    You can tune the model's behavior, point it at your own notes or documents, and build specialized workflows for school, research, coding, or engineering projects.
  </Accordion>
</AccordionGroup>

## Open source vs. closed source

<CardGroup cols={2}>
  <Card title="Open source / open weight" icon="lock-open">
    - Model weights can be downloaded.
    - Can run locally on your own device or server.
    - More privacy and control.
    - Community can test, fine-tune, and build on top of it.
    - **Examples:** Llama, Qwen, DeepSeek, Gemma, Mistral.
  </Card>
  <Card title="Closed source / proprietary" icon="lock">
    - Accessed through an app or API only.
    - Weights are not public.
    - Easier to use; less control.
    - Data handling and cost depend on the provider.
    - **Examples:** ChatGPT, Claude, Gemini.
  </Card>
</CardGroup>

## Big models vs. small models

<CardGroup cols={2}>
  <Card title="Large (30B – 2T+ parameters)" icon="warehouse">
    - Better general reasoning.
    - Handles more complex tasks.
    - Usually needs cloud GPUs or big servers.
    - More expensive to run.
    - **Good for:** coding, research, planning, agents.
  </Card>
  <Card title="Small (under 20B parameters)" icon="microchip">
    - Faster and cheaper to run.
    - Runs on laptops, phones, or modest local servers.
    - Better when focused on one task.
    - Easier to customize or fine-tune.
    - **Good for:** tutoring, classification, privacy-sensitive tasks, simple assistants.
  </Card>
</CardGroup>

## Step-by-step setup

You need two free desktop apps and two open-weight models. Follow these five steps in order. If you're at the workshop, the USB has everything preloaded — see the [USB shortcut](#workshop-day-usb-shortcut) below.

<Steps>
  <Step title="Download and install Ollama">
    Open [**ollama.com/download**](https://ollama.com/download) and grab the installer for your OS (Mac, Windows, or Linux). Run it.

    Ollama is the local model server — it runs in the background and exposes a local API that other apps can talk to. After install, you should see the Ollama icon in your menu bar (Mac) or system tray (Windows).
  </Step>
  <Step title="Download and install AnythingLLM">
    Open [**anythingllm.com/desktop**](https://anythingllm.com/desktop) and grab the desktop app for your OS. Run the installer.

    AnythingLLM is the chat front-end — the part that looks like ChatGPT but talks to your local Ollama instead of OpenAI.
  </Step>
  <Step title="Pull the two workshop models">
    Open a terminal (macOS: **Terminal.app**; Windows: **PowerShell** or **Command Prompt**) and run:

    ```bash
    ollama pull gemma4:e2b
    ollama pull qwen3.5:0.8b
    ```

    `gemma4:e2b` is the main workshop model. `qwen3.5:0.8b` is the smaller alternate. Both will download from [ollama.com/library](https://ollama.com/library) in the background — total around 4-5 GB.
  </Step>
  <Step title="Open AnythingLLM and connect to Ollama">
    Launch **AnythingLLM**. In the onboarding screens:

    - **LLM provider:** Ollama
    - **Model:** `gemma4:e2b`
    - Click through the remaining onboarding screens (workspace name, telemetry choice, etc.).
  </Step>
  <Step title="Start chatting">
    You're now running an AI model entirely on your own laptop. No cloud, no API key, no internet required after this point.

    To swap models later, open AnythingLLM's settings → **LLM Preference** → pick `qwen3.5:0.8b`. It only loads into memory when selected.
  </Step>
</Steps>

<Tip>
  **Want to skip Ollama's CLI?** AnythingLLM can pull models for you. Once Ollama is installed, AnythingLLM will detect it and let you pull `gemma4:e2b` from inside its UI.
</Tip>

## The agent activity — search local files

The headline hands-on moment of the workshop. Instead of explaining vector databases first, you point the agent at a folder and watch it search.

<Steps>
  <Step title="Open AnythingLLM with Gemma loaded">
    From the setup steps above. Ollama running in the background, Gemma selected as the model.
  </Step>
  <Step title="Open the prompt sheet">
    `References to Search Through/FILE-SEARCH-AGENT-PROMPTS.md` — this has copy-paste prompts you can run.
  </Step>
  <Step title="Point the agent at the references folder">
    Replace `PATH_TO_THIS_FOLDER` with the actual path on your machine, then send:

    ```
    @agent Search PATH_TO_THIS_FOLDER for Gemma 4 and qwen3.5. Read the most
    relevant files and compare the two models for this workshop.
    ```
  </Step>
  <Step title="Ask for an output">
    The agent can summarize, compare, cite filenames, and create new files from what it found. Try:

    - *"Write a one-page summary of how Empire AI access works."*
    - *"List the SLURM commands mentioned in the HPCC docs."*
    - *"Compare Gemma 4 E2B and Qwen 3.5 0.8B head to head."*
  </Step>
</Steps>

## After the workshop

If you keep using local models, the natural next steps are:

- **Run a larger model** if your laptop has the RAM. Try `gemma3:12b` or `qwen3:14b` from `ollama pull`.
- **Move to a real GPU** via the [CSI HPCC](/index) or, for bigger work, [Empire AI](/empire-ai/index).
- **Wire local models into your IDE** — Continue, Cursor, and Aider all support an Ollama endpoint.
- **Read the open-weight model cards** on [Hugging Face](https://huggingface.co/) before downloading new models — licenses vary widely.
